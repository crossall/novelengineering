요구 사고 · 명세(정의) → 검증 → 되돌아가기(메타인지)

내가 만들 것을 정하고(명세), AI에게 보낼 글로 바꾸고(프롬프트), AI가 준 코드를 여기서 실행하고, 세 가지 경우로 확인합니다(검증). 실패하면 명세로 돌아갈지 프롬프트를 고칠지 내가 정합니다. 몇 바퀴 돌았는지 세어 둡니다.

1단계 · 명세

짧게. 하지만 확인할 수 있게.

"~이면 ~한다"처럼, 숫자를 넣어서.

2단계 · 프롬프트

명세가 그대로 글이 됐어요. 고치고 싶으면 1단계로 돌아가 명세를 고칩니다.

이 프롬프트를 AI(클로드, 제미나이 등)에 붙여 넣고, 돌아온 HTML 코드를 전부 복사해 오세요. 선생님과 함께 해도 좋아요.

3단계 · 실행

AI가 준 HTML 코드를 아래에 붙여 넣고 "실행"을 누릅니다. AI가 없으면 "예시 코드 불러오기"로 해 볼 수 있어요.

4단계 · 검증

"예상"을 먼저 적고, 3단계 화면에서 해 본 다음 "실제"를 적어요. 명세의 성공 조건과 비교합니다.

성공 조건에서 카드를 만들어 줘요.
3개 중 0개 통과 아직

실패한 카드가 있어요. 예상이 틀렸거나 애매했다면 명세를, 예상은 맞는데 AI가 다르게 만들었다면 프롬프트를 고칩니다.

    교사 노트. 수업 사용법: 학생 한 명(또는 모둠)이 명세를 채우면 2단계 프롬프트를 교사 계정의 AI에 붙여 넣고, 돌아온 코드를 학생이 3단계에 붙여 실행합니다. 실행 화면은 격리된 틀(sandbox) 안에서만 돌아가므로 이 페이지의 저장 데이터에 닿지 못합니다. 4단계에서 실패가 나오면 학생이 "명세로 돌아가기"와 "프롬프트 고치기" 중 하나를 고르게 하고, 바퀴 수를 함께 봅니다. 관찰 포인트: 1단계에서 성공 조건에 숫자를 넣는가. 4단계에서 "예상"을 먼저 적는가, 결과를 보고 예상을 바꾸지는 않는가. 실패의 원인을 명세 쪽으로 돌리는지 AI 쪽으로 돌리는지 — 이것이 메타인지의 갈림길입니다. 이 앱의 명세 — 기능: ① 짧은 명세 입력(이름·인물·기능 3·성공 조건 3) ② 프롬프트 자동 생성·복사 ③ 붙여 넣은 HTML을 격리된 틀에서 실행 ④ 예시 코드 내장 ⑤ 검증 카드 3장과 되돌아가기 바퀴 수 기록. 입력: 명세 칸, HTML 텍스트, 카드 입력·예상·실제·결과. 출력: 프롬프트 텍스트, 실행 화면, "3개 중 N개 통과", "지금까지 N바퀴 돌았어요". 성공 조건: 성공 조건 3개가 비면 2단계로 못 넘어간다 / HTML 표시가 없는 글을 실행하면 안내가 뜬다 / 실패 카드가 있으면 되돌아가기 버튼 2개가 나타나고 누르면 바퀴 수가 1 늘어난다 / 새로고침해도 단계와 입력이 남아 있다.
